# HUD для Audi A4 B9 (MLB-Evo) — ESP32-S3 Super Mini / NV3007 2.79″ / BLE — v31.0.0

[English](README.md) · [Приложение Android](https://github.com/WARMW00D/HUD-Audi-A4-B9-MLB-Evo-Android-App)

Самодельный HUD показывает данные с Infotainment CAN Audi (MLB-Evo) или Comfort CAN (MQB): скорость, передачу, ACC, лимитер, ассистентов, дорожные знаки, двери и навигацию. Это компактная адаптация [проекта Waveshare 3.49″](https://github.com/WARMW00D/HUD-Audi-A4-B9-MLB-Evo-Waveshare-ESP32-S3-Touch-LCD-3.49) под **NV3007 428 × 142**, с настройками и обновлением прошивки по BLE через Android.

**Проверенная конфигурация автомобиля:** работа устройства проверялась на **Audi A4 B9 рестайлинг (facelift) с магнитолой MIB3 High**.

**Прошивка: v31.0.0. Приложение: 1.5.0.** Здесь исходники прошивки и схема соединений. Android вынесен в отдельный репозиторий. Готовый app-BIN в Releases ниже — v30.0.0 (v30.0.1 меняет только дорожную графику навигации и строку версии); там же APK 1.5.0.

## Объём бака, бар ускорения и толерантность

Версии исходников: **прошивка HUD v31.0.0 / приложение Android 1.5.0 (versionCode 7)**.

- **Объём бака:** целое число от **1 до 200 литров**, по умолчанию **54 л**. Всегда вводится в литрах, даже при отображении галлонов США, и меняет расчёт долива на HUD.
- **Бар ускорения:** включается и выключается через приложение. Использует имеющиеся данные ускорения/скорости; на стоянке и без достоверных данных остаётся пустым.
- **Толерантность превышения:** **0–100 км/ч**, по умолчанию **20 км/ч**; всегда вводится в км/ч, даже при отображении mph. Цифры скорости плавно переходят от белого к красному от 75% допуска до 100%; при нуле красный цвет включается сразу при превышении.
- Все три настройки подтверждаются чтением BLE и сохраняются в NVS HUD. Прежние настройки, владелец телефона и ключи шлюза сохраняются. Сброс привязки телефона кнопкой BOOT тоже сохраняет эти значения.

Для новых настроек нужны **приложение 1.4.1 или новее + прошивка v30.0.0**. Приложение 1.4.1 работает и со старой прошивкой: отсутствующие настройки отключены. Готовые APK 1.4.1 и app-BIN v30.0.0 от WARMW00D опубликованы в Releases; целостность проверена. Если уже установлена v30.0 с OTA-разделами, v30.0 использует ту же разметку; для более ранних прошивок сначала нужен переход через USB по инструкции ниже.

## Изменения v31.0.0

- Дисплей: новый асинхронный вывод по SPI с DMA (`HUD_LCD_ASYNC_DMA`, включён по умолчанию). Два буфера отрисовки позволяют LVGL рисовать следующую полосу, пока предыдущая ещё уходит по SPI. Значение 0 возвращает прежний блокирующий путь. `HUD_LCD_DMA_SPI_HZ` — частота (по умолчанию 20 МГц; 40 МГц пробовать только с проверкой картинки), `HUD_PERF_LOG` печатает в Serial время отрисовки и передачи.
- Звук: необязательный динамик на GPIO7 через BC547 (`hud_sound`): короткий сигнал, двойной, нарастающий и предупреждающий. При старте проигрывается короткая мелодия (`HUD_SOUND_STARTUP`).
- Пины: GPIO10–13 зарезервированы под флеш W25Q128 на отдельной шине SPI (питание от 3V3_D, как у дисплея). Необязательный датчик света переехал на `HUD_LDR_PIN` (по умолчанию GPIO14, ADC2).
- Схемы соединений: рисунки `new_pins` (EN/RU) теперь показывают динамик, W25Q128 и датчик света.
- Навигация: стрелки и дороги взяты из проекта Waveshare (`tools/gen_nav_images.py`, родная область 192 × 116). Боковой бар дистанции убран, его место занимает увеличенная область стрелки. Дистанция до манёвра стоит на уровне скорости ACC. Пока манёвр далеко, дороги не видно, по мере приближения она заливается стандартным серым снизу вверх (те же данные `bargraph`, что раньше шли в бар). Расстояние до камеры выводится крупным шрифтом маршрута без пробела (`330м` / `330m`).
- Камеры: позиция и курс GPS берутся из CAN автомобиля (NavPos_01 0x486, NavData_01 0x484). База `cams.bin` (из `gen_cams.py`) лежит во флеше W25Q128 и при старте загружается в PSRAM; `cam_alert` находит ближайшую камеру впереди двоичным поиском, файл индекса не нужен. Знак (жёлтый квадрат, диск с ограничением, значок камеры, расстояние) и окраска цифр скорости повторяют дизайн Waveshare; при превышении лимита камеры звучит сигнал (`HUD_CAMS`, `HUD_CAM_*` в `hud_config.h`).
- Показ камер, сигнал у камеры и громкость звука (0–100 %, 0 — без звука) переключаются из приложения Android (новые BLE-настройки `…000D`, `…000E`, `…000F`, хранятся в NVS).
- Загрузка базы камер из приложения Android по BLE потоком, с автоматическим повтором и без перезагрузки: `docs/CAMS_UPLOAD_ru.md`. Нужно приложение **1.5.0**.
- MQB (ранняя поддержка): новый переключатель `HUD_PLATFORM` в `hud_config.h` (по умолчанию `HUD_PLATFORM_MLB_EVO`, либо `HUD_PLATFORM_MQB`). На MQB ACL и декодер берут ACC из `0x2A7` / `0x30C` (активность, заданная скорость, машина впереди), пропускают отсутствующие `0x2A9` / `0x64F` и читают регулятор яркости из `0x5F0`. Проверено только на логах Skoda Octavia A7 через проигрыватель; таблица сигналов и открытые вопросы — в разделе «Платформа автомобиля: MLB-Evo и MQB» ниже.

## Что показывает HUD

| Элемент | Поведение |
|---|---|
| Скорость и КП | Цифровая скорость приборки; P/R/N/D/S/M/E/Offroad и номер передачи, если доступен |
| ACC и лимитер | Установленная скорость, цель впереди, режим пробки; LIM вместо значка установки ACC |
| Lane / Side Assist | Линии полосы, удержание и предупреждения; красные линии для мёртвых зон |
| Знаки | Основной знак: действующий VZE → явный PSD → PSD по правилам; дополнительные меняются по кругу |
| Превышение | Плавный переход цифр скорости от белого к красному относительно основного ограничения |
| Навигация | Основной и следующий манёвры, дистанция, шкала, расстояние и время до цели |
| Двери / pre sense | Открытые части машины вместо навигации; pre sense имеет приоритет |
| Поворотники | Зелёные стрелки; аварийка — красные |
| Топливо | Объём долива и полоса расхода при наличии нужных данных |
| Ускорение | Шкала включается в приложении; по умолчанию выключена |
| Яркость | Датчик освещённости машины × колёсико; ночью **2–40**, на солнце **200–255** |
| Настройки | PSD, VZE, язык HUD, единицы скорости/дистанции и объёма; сохраняются в NVS |

Поля с устаревшими данными скрываются. Отображение зависит от наличия сигналов на шине конкретной машины. В этой версии нет сенсора, аудиокодека и SD-журнала Waveshare; настройки меняются с телефона. Язык приложения выбирается отдельно от языка HUD.

## Архитектура

HUD декодирует сырые кадры локально в `can_decode.c`. Источник выбирается в `supermini_hud/hud_config.h`:

| Режим | Источник |
|---|---|
| `HUD_SRC_AUTO` — по умолчанию | Свой CAN, пока идут кадры; после 1 с тишины — BLE-шлюз |
| `HUD_SRC_TWAI` | Прямой CAN через TJA1051T/3, TWAI `LISTEN_ONLY` |
| `HUD_SRC_BLE` | Сырые CAN-кадры совместимого шлюза / сниффера |
| `HUD_SRC_FAKE` | Встроенный генератор для стенда |

[Сниффер / BLE-шлюз](https://github.com/WARMW00D/esp32-CAN-sniffer-logger-screener) использует ACL-протокол, прошивка 2.6.0+. HUD передаёт ACL после каждого соединения. Настройки телефона и OTA — отдельные GATT-сервисы; NimBLE одновременно работает клиентом шлюза и сервером телефона. Первое PIN-сопряжение шлюза откладывается, если подключён телефон.

LVGL рисует сразу в физическом разрешении 428 × 142 и передаёт по SPI только изменившиеся полосы. В тестовой сборке v30.0.0 шаг масштабирования 518 × 172 → 428 × 142 удалён; частичный буфер размещается во внутренней RAM. Не добавляйте вызовы LVGL из BLE callbacks.

[Сигналы CAN и протокол шлюза](docs/CAN_ru.md) · [Настройки BLE](supermini_hud/BLE_SETTINGS_ru.md)

## Железо и подключение

- **ESP32-S3 Super Mini:** проект рассчитан на предоставленную плату с 4 MB Flash / 2 MB QSPI PSRAM. Сверьте вариант своей платы.
- **NV3007 2.79″:** 428 × 142, SPI, логический вход управления подсветкой.
- **TJA1051T/3:** CAN-модуль с VIO и логическим интерфейсом 3,3 В.
- ACC 12 В → внешний DC-DC 12→5 В. Общая линия 5V питает ESP32 и **вход** отдельного DC-DC 5→3,3 В для дисплея.

**VDD дисплея получает 3,3 В от отдельного преобразователя (`3V3_D`). Его выход не соединяется с 3V3 платы (`3V3_P`).** Все GND общие. CAN VCC питается от 5V платы; VIO и S — от 3V3 платы. SN65HVD230 не используется.

![Схема HUD, ревизия 3](schematics/HUD_supermini_NV3007_rev3_ru_new_pins.png)

[Редактируемый SVG](schematics/HUD_supermini_NV3007_rev3_ru_new_pins.svg) · [PDF](schematics/HUD_supermini_NV3007_rev3_ru_new_pins.pdf)

| ESP32-S3 | Подключение |
|---|---|
| GPIO1 | LCD SCL / SPI SCK |
| GPIO2 | LCD SDA / SPI MOSI |
| GPIO5 | LCD CS |
| GPIO4 | LCD DC |
| GPIO3 | LCD RES |
| GPIO6 | LCD BL / PWM |
| GPIO8 | CAN CRX / RXD |
| GPIO9 | TWAI TX → CAN CTX / TXD (подключить; в `LISTEN_ONLY` контроллер держит его в рецессиве) |
| GPIO0 | Встроенная кнопка BOOT |

CAN CTX/TXD → GPIO9; S → VIO для silent mode. Не оставляйте CTX/TXD в воздухе: плавающий TXD не на каждом модуле гарантированно остаётся рецессивным. CAN-H / CAN-L — витая пара. Терминацию 120 Ω модуля отключить при подключении к уже терминированной шине автомобиля. Только приём обеспечивается режимом TWAI `LISTEN_ONLY` и аппаратным Silent (S → VIO); Silent держит передатчик выключенным и во время загрузки и сброса ESP32. SCL/SDA дисплея здесь означают SPI, а не I²C; MISO не используется. Если BL напрямую питает светодиоды, а не является логическим входом, нужен подходящий внешний драйвер.

Это схема соединений, не разводка PCB и не полная схема автомобильной защиты питания. Развязка USB-питания не показана; учитывайте её при прошивке с подключённым внешним 5V.

## Сборка и первая установка через USB

Открыть `supermini_hud/supermini_hud.ino` в Arduino IDE. Имя папки скетча должно остаться `supermini_hud`.

| Параметр | Конфигурация проекта |
|---|---|
| Плата | ESP32S3 Dev Module |
| Arduino ESP32 core | 3.3.10, как в предоставленной рабочей конфигурации |
| CPU | 240 MHz |
| Flash | 4 MB, QIO / 80 MHz, согласно рабочим параметрам платы |
| PSRAM | QSPI, 2 MB; не OPI |
| USB CDC On Boot | Enabled |
| Таблица разделов | Свой файл `supermini_hud/partitions.csv` |
| Serial | 115200 |
| Библиотеки | LVGL 8.4.0; NimBLE-Arduino 2.x / API 2.5.1; Arduino_GFX с `Arduino_NV3007` |

Разместить `supermini_hud/config/lv_conf.h` рядом с установленной папкой `lvgl/`. Обязательно: `LV_COLOR_DEPTH 16`, `LV_USE_FONT_COMPRESSED 1`. LVGL 9 не поддерживается. Драйвер учитывает оба варианта `LV_COLOR_16_SWAP`.

**Переход v28.x → v30.0 впервые делается через USB с новой таблицей разделов. Erase All Flash = Disabled.** Проверить применение CSV из проекта и запись таблицы по адресу 0x8000; один app `.bin` не меняет разметку. NVS остаётся на 0x9000 размером 0x5000: настройки и сопряжения должны сохраниться, но это необходимо подтвердить на устройстве.

Два OTA-раздела по **0x1F0000 / 2 031 616 байт**. Проверить размер после сборки. При запуске ожидаются `[fw] HUD Super Mini v31.0.0 / BLE OTA` и capacity следующего раздела 2031616.

Для защищённого шлюза скопировать `secrets.example.h` в `secrets.h` и задать тот же `BLE_PASSKEY`, что на шлюзе. `secrets.h` исключён из Git. PIN телефона `HUD_SETTINGS_PIN` в `user_config.h` — отдельный код.

## Опциональный датчик света

SuperMini может использовать фоторезисторный делитель на **пине `HUD_LDR_PIN`** (по умолчанию GPIO14, ADC2; GPIO10–13 зарезервированы под W25Q128, GPIO7 — под динамик), если нет данных освещённости RLS_01. Подключите фоторезистор от 3V3 к этому пину, резистор 10 кОм от пина к GND и при необходимости конденсатор 100 нФ от пина к GND. Калибровка выполняется в Android: полностью закройте сенсор и один раз сохраните точку «темно», затем посветите ярким фонариком и один раз сохраните точку «ярко».

## Настройки Android и BLE OTA

1. Скачать APK выше либо собрать и установить [Android-приложение](https://github.com/WARMW00D/HUD-Audi-A4-B9-MLB-Evo-Android-App).
2. Найти `HUD-SuperMini`, подключиться и завершить системное сопряжение. PIN телефона: см. `HUD_SETTINGS_PIN` в [`user_config.h`](supermini_hud/user_config.h).
3. Первый аутентифицированный телефон становится владельцем. Изменения настроек читаются обратно и сохраняются в NVS.
4. Для OTA экспортировать **`supermini_hud.ino.bin`** из Arduino IDE. Выбрать этот app-образ в приложении и подтвердить обновление.
5. Сохранять стабильное питание и открытое приложение. После проверки и выбора boot-раздела HUD перезапустится; подключиться вновь и проверить работу.

Для OTA не подходят bootloader, partitions, merged-образ и полный дамп. Проверяются смещения, SHA-256, заголовок приложения ESP32-S3 и образ ESP-IDF до выбора нового раздела. Доступ — только сохранённому аутентифицированному владельцу. Потеря финального подтверждения может означать, что раздел уже переключён: дождаться перезапуска и проверить HUD перед повтором. Автоматический откат неисправной новой программы не гарантируется; восстановление — через USB.

Для смены телефона: на работающем HUD удерживать **BOOT 5 с и отпустить**. Сбрасываются только владелец и ключи телефона; настройки HUD и ключи шлюза остаются. Удалить прежнее сопряжение на телефоне перед повторной привязкой. Не держать BOOT при включении питания/reset.

[Полная инструкция OTA](docs/OTA_ru.md) · [OTA guide in English](docs/OTA.md)

## Конфигурация и диагностика

`user_config.h`: GPIO LCD, ориентация, смещения, частота SPI, имя/PIN телефона и BOOT. `hud_config.h`: источник данных, начальные настройки знаков/единиц, бак, яркость и Serial-журнал. Сохранённые настройки телефона имеют приоритет над начальными константами.

| Настройка | По умолчанию |
|---|---|
| `HUD_CAN_RX_PIN` / `HUD_CAN_TX_PIN` | 8 / 9, TX подключён к CTX/TXD |
| `HUD_CAN_BITRATE_K` | 500 |
| `HUD_LCD_SPI_HZ` / `HUD_LCD_ROTATION` | 20 MHz / 1 |
| `HUD_BR_DARK_WHEEL_MIN` / `_MAX` | 2 / 40 |
| `HUD_BR_BRIGHT_WHEEL_MIN` / `_MAX` | 200 / 255 |
| `HUD_LANG` / `HUD_UNITS` | RU / km |
| `HUD_TANK_L` | 54 л |

Для стенда использовать `HUD_SRC_FAKE` или совместимый BLE-проигрыватель логов. `HUD_LOG_CAN` / `HUD_LOG_STAT` помогают искать пропавшие кадры; скрытие поля по таймауту не обязательно означает ошибку графики. `tools/can_bitdiff.py` показывает меняющиеся биты CAN.

| Симптом | Что проверить |
|---|---|
| Нет текста кастомными шрифтами | `LV_USE_FONT_COMPRESSED 1`, LVGL 8 |
| Чёрный экран / ошибка памяти | QSPI PSRAM, GPIO, питание, ориентация и смещения LCD |
| Нет данных шлюза | ACL-протокол, имя, сопряжение/passkey и режим источника |
| Нет OTA-сервиса | Установка v30.0 через USB, переподключение после Service Changed, capacity |
| Нет подключения после удаления Android bond | Сбросить владельца BOOT, затем сопрячь заново |

## Платформа автомобиля: MLB-Evo и MQB

`HUD_PLATFORM` в `hud_config.h` (или `-DHUD_PLATFORM=HUD_PLATFORM_MQB`) выбирает карту сигналов: `HUD_PLATFORM_MLB_EVO` (по умолчанию, Audi A4 B9 и другие MLB-Evo, проверено) или `HUD_PLATFORM_MQB` (VAG MQB, ранняя поддержка сообществом). Всё, что не связано с шиной (интерфейс, камеры, меню, OTA), общее. Список ACL для сниффера/шлюза и декодер переключаются вместе с платформой.

**Шина:** на MLB-Evo HUD подключается к Infotainment CAN, на MQB — к Comfort CAN (500 кбит/с в обоих случаях); на схемах обе подписи.

Цвета проводов на разъёме автомобиля:

| Линия | MLB-Evo | MQB |
|---|---|---|
| CAN-H | фиолетовый | оранжево-зелёный |
| CAN-L | оранжево-коричневый | оранжево-коричневый |

К CAN-модулю подключайте витой парой. Перед подключением проверьте цвета на своём автомобиле.

MQB проверен только по логам одной Skoda Octavia A7 (до рестайлинга, с установленным Virtual Cockpit), прогнанным через BLE-проигрыватель; саму приборку не снимали, поэтому ⚠️ означает гипотезу по логу.

| Сигнал | MLB-Evo | MQB | Статус на MQB |
|---|---|---|---|
| Скорость, передача, поворотники, двери, знаки (VZE), Side Assist | те же кадры | те же кадры | работает на проигрывателе |
| ACC активен | `0x2A8` 16\|3 | `0x2A7` бит 58 | ⚠️ совпадает с `0x30C` бит 61 по времени |
| Заданная скорость ACC | `0x2A6` 12\|10, ×0.32 км/ч | `0x30C` 16\|6: 5·v+5 км/ч, 63 = не задана | ⚠️ значения 5/7/9/11/19 дают 30/40/50/60/100 |
| Машина впереди, зазор | `0x2A6` 45\|2 / 37\|3 | `0x30C` 45\|2 / 37\|3 | ⚠️ предположена та же раскладка |
| Ведение по полосе в ACC, режим пробки | `0x2A6` 7\|2 / 62\|2 | не разбираются | нет |
| Pre sense | `0x2A9` | кадра нет | отключено |
| Lane Assist | `0x397` | `0x397`, тот же декодер; ACL без ограничения частоты (зелёный держится 0,1–1 с) | работает; флаги предупреждения в логе не встречались |
| Яркость | `0x5F0` + датчик света `0x5A0` + колёсико `0x64F` | `0x5F0` байт 0; колёсико из `0x5F0` байт 2 (16\|8); `0x5A0` и `0x64F` нет | ⚠️ байт колёсика виден только на 100 (фары выключены) |

Кадры получены из логов Octavia A7 через настоящий декодер и интерфейс (хост-рендер панели 428×142; знаки ограничения скорости, ACC с машиной впереди, линии Lane Assist):

![Экраны MQB: ACC, Lane Assist, навигация](docs/images/mqb-screens.png)

![Знаки ограничения скорости MQB из VZE](docs/images/mqb-signs.png)

Открыто для тех, кто будет развивать MQB: подтвердить биты ACC по приборке, найти ведение по полосе и режим пробки, поведение датчика света и колёсика при включённых фарах, стрелки навигации (BAP отличается от MLB-Evo), путь данных с двух шин (Powertrain/Comfort).

## Статус проверок

WARMW00D предоставил app-BIN ESP32-S3 v30.0.0 и APK Android v1.4.1. Контрольная сумма/SHA-256 прошивки, подписи и целостность APK проверены. Host-тесты проходят. Здесь сборки не запускались; Android lint не выполнялся. Владелец проекта подтвердил OTA по BLE на реальном железе.

Host-тесты с настоящим SHA-256 через OpenSSL и заглушками NimBLE/ESP-IDF: полная передача, переключение только после проверки, неверные размер/заголовок/чип/hash, ошибки Flash, смещения, отмена/обрыв/таймаут, доступ владельца, повтор COMMIT и потеря последнего ACK. Есть также тесты масштаба, изменившихся полос, декодера и настроек/NVS. Заглушки не подтверждают работу реального BLE и Flash.

Пример из `supermini_hud/` (нужны g++ и заголовки OpenSSL):

```sh
g++ -std=c++17 -Wno-deprecated-declarations -Itests/settings_stubs tests/test_ble_ota.cpp -lcrypto -o /tmp/hud_test_ota
/tmp/hud_test_ota
g++ -std=c++17 -Wno-deprecated-declarations -Itests/settings_stubs tests/test_ble_settings.cpp -lcrypto -o /tmp/hud_test_settings
/tmp/hud_test_settings
```

Проверка CAN зависит от машины и комплектации. Наблюдения исходного проекта и неизвестные сигналы указаны в [справочнике CAN](docs/CAN_ru.md). Контроль целостности не является цифровой подписью или гарантией совместимости сторонней прошивки ESP32-S3.
