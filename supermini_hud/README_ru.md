# HUD Super Mini / NV3007 — вариант v29.0

Исходная версия: приложенный waveshare_hud_v27_1.zip.
Плата: ESP32-S3 Super Mini, 4 MB Flash / 2 MB QSPI PSRAM.
Дисплей: NV3007 2.79", 142×428 в портретной ориентации, 428×142 в альбомной.

## OTA v29.0

BLE OTA через Android HUD Control 1.2. Первую установку выполнить через USB
вместе с новым partitions.csv, без полного стирания. См. **../docs/OTA_ru.md**.

## Изменения

- Удалены тач и экранное меню настроек. Язык, единицы и PSD/VZE меняются
  по BLE и сохраняются в NVS вместе с владельцем; hud_config.h задаёт значения
  по умолчанию. Остальные графические параметры задаются константами.
- Удалены звук, PCM-файлы, кодек ES8311, I²S и расширитель GPIO TCA9554.
  Side Assist сохраняет визуальные предупреждения, звуков нет.
- Удалены SD-драйвер и файловое логирование, задача записи и буфер журнала.
  Убраны подписка BLE на Diagnose_01 0x6B2 и декодер часов, использовавшийся
  только для имён файлов и временных меток SD-журнала. Диагностика в Serial остаётся.
  Navigation_SD в названиях BAP — имя автомобильного сервиса навигации,
  к физической SD-карте HUD оно отношения не имеет и сохранено.
- QSPI-дисплей AXS15231B заменён на обычный SPI NV3007 через Arduino_GFX.
  Плата Waveshare, SensorLib и её драйверы больше не нужны.
- Сохранены CAN-декодирование остальных сигналов, BLE ACL, TWAI LISTEN_ONLY,
  AUTO/BLE/TWAI/FAKE, автояркость, ассистенты, двери, PSD/VZE, маршрут и расход.

## Раскладка на весь экран

Сначала ширина зоны навигации уменьшена **192 → 128** (ровно в 1.5 раза).
Основные стрелки пересозданы с пропорциональным уменьшением **192×116 → 128×77**;
они центрированы по высоте над прежней строкой дистанции.
Малые стрелки: 38×23 → 25×15. Машинка и PreSense центрированы в узкой зоне.
Свободные горизонтальные промежутки между блоками сокращены; поля выравнивания
скорости и передачи укорочены без изменения размера шрифта. Три цифры скорости
помещаются в поле 244 пикселя (табличный шаг цифры около 81.2 пикселя).
Бар дистанции сделан тоньше, сегменты бара ускорения уплотнены под новую ширину.

Итоговая логическая раскладка **518×172** масштабируется на весь **428×142**:
коэффициент по X 0.82625, по Y 0.82558. Разница менее 0.1%, вызвана округлением
до целых пикселей. Дополнительных чёрных полей и обрезки кадра нет.
Используется билинейное масштабирование RGB565, чтобы сгладить мелкий текст.

Один кадр LVGL занимает **178192 байта PSRAM**; выходной блок 428×8 —
**6848 байт внутренней RAM**. Буфер предыдущего изображения для сравнения полос
занимает ещё **121552 байта PSRAM**; отдельного буфера поворота нет.
Остальная память расходуется LVGL, BLE и исходной логикой. Общий расход памяти,
скорость обновления и размер прошивки требуется измерить после сборки на плате.

## Подключение дисплея

Пины выбраны для этой версии, существующую проводку при необходимости изменить
в user_config.h. Номера GPIO не равны порядковым номерам контактов платы.
На модуле подписи SCL/SDA обозначают **SPI SCK/MOSI**, это не I²C.

| Контакт дисплея | Super Mini | Параметр |
|---|---|---|
| GND | GND | общая земля |
| VDD | 3V3_D выхода DC-DC 5 → 3,3 В | согласно приложенному описанию, VDD допускает 3–5 V |
| SCL | GPIO4 | HUD_LCD_SCK |
| SDA | GPIO5 | HUD_LCD_MOSI |
| RES | GPIO6 | HUD_LCD_RST |
| DC | GPIO7 | HUD_LCD_DC |
| CS | GPIO2 | HUD_LCD_CS |
| BL | управление от GPIO1 | EXAMPLE_PIN_NUM_BK_LIGHT |

Сигналы управления — 3.3 V. MISO не используется.
**BL:** в описании указан ток светодиодов 100 mA, но полная схема модуля
не приложена. GPIO1 можно подключать напрямую только к логическому входу
установленного на модуле драйвера подсветки. Если BL питает светодиоды напрямую,
нужен внешний транзисторный/токовый драйвер; 100 mA через GPIO не подавать.
По умолчанию яркость активна высоким уровнем. Для инверсного входа/драйвера
поставить HUD_BL_ACTIVE_HIGH 0. Частота PWM — 5 kHz.

SPI по умолчанию 20 MHz. При нестабильном изображении снизить HUD_LCD_SPI_HZ
до 10000000. HUD_LCD_ROTATION 1 — альбомная ориентация, 3 — переворот на 180°.
HUD_LCD_COL_OFFSET_1/2 = 12/14 соответствует конфигурации NV3007 142×428
в официальном примере Arduino_GFX. HUD_LCD_INVERT можно переключить 0/1,
если конкретному модулю требуется инверсия панели.

## Источник данных

Сохранён исходный HUD_DATA_SOURCE = HUD_SRC_AUTO. Если собственного CAN-трансивера
нет, предпочтительно выбрать **HUD_SRC_BLE** в hud_config.h.
Для проверки без машины: **HUD_SRC_FAKE**. Имя шлюза: S3-CAN-Sniffer.
BLE-шлюз/сниффер должен поддерживать исходный ACL-протокол (прошивка 2.6.0+).
Если включена защита, скопировать secrets.example.h в secrets.h и вписать
тот же BLE_PASSKEY, что у шлюза.

Для схемы с TJA1051T/3: VCC → 5V платы, VIO и S → 3V3 платы,
GND общая. CRX/RXD → GPIO8. CTX/TXD подтянуть 10 кΩ к VIO.
GPIO9 оставить неподключённым (TWAI LISTEN_ONLY). Терминацию 120 Ω на модуле
отключить при подключении к уже терминированной шине автомобиля.
VDD дисплея питается от отдельного DC-DC 5 → 3,3 В; вход преобразователя —
от общей линии 5V. Выход DC-DC не соединять с контактом 3V3 ESP32-S3.

## Сборка Arduino IDE

Открыть **supermini_hud/supermini_hud.ino**. Имя папки и скетча должно совпадать.

| Настройка | Значение |
|---|---|
| Плата | ESP32S3 Dev Module |
| ESP32 Arduino core | 3.3.10 — версия из приложенного отчёта платы |
| CPU | 240 MHz |
| Flash Size | 4 MB |
| Flash Mode / Frequency | QIO / 80 MHz, как в рабочей конфигурации вашей платы |
| PSRAM | QSPI PSRAM, 2 MB; не OPI |
| USB CDC On Boot | Enabled |
| Partition Scheme | файл partitions.csv в папке скетча |

В partitions.csv теперь **два OTA-приложения app0/app1 по 0x1F0000**
(1984 KiB), otadata, NVS и coredump. Файловой системы нет. В выводе сборки
проверить применение файла из папки скетча. Максимум app .bin: 2031616 байт.
Для перехода с v28.x нужно впервые загрузить новую таблицу через USB.

Библиотеки:

- **lvgl 8.4.0**. LVGL 9 не подходит.
- **NimBLE-Arduino 2.x**; исходный BLE-код рассчитан на API 2.5.1.
- **GFX Library for Arduino** (Arduino_GFX), актуальная версия с Arduino_NV3007
  и поддержкой ESP32 Arduino core 3.3.10. Сам архив эту библиотеку не содержит.

Скопировать **config/lv_conf.h** рядом с каталогом установленной библиотеки lvgl:
Documents/Arduino/libraries/lv_conf.h и Documents/Arduino/libraries/lvgl/.
Критично: LV_COLOR_DEPTH 16 и LV_USE_FONT_COMPRESSED 1.
**LV_COLOR_16_SWAP может быть 0 или 1**: драйвер автоматически учитывает
активную настройку LVGL до масштабирования и передаёт Arduino_GFX обычный RGB565.
Буфер LVGL при этом не изменяется. Можно оставить общий lv_conf.h с
LV_COLOR_16_SWAP 1 для Waveshare и собирать оба проекта без переключения этой
настройки. Если общий lv_conf.h уже работает на Waveshare, заменять его файлом
config/lv_conf.h не требуется; этот файл — пример для новой установки.

Serial: 115200. При отключённой/неверно выбранной PSRAM прошивка выдаёт
диагностическое сообщение и останавливается. Успешное начало SPI не доказывает,
что экран физически подключён правильно: обратного чтения дисплея нет.

## Проверки и ограничения

В этом окружении **нет Arduino/ESP32 toolchain**, поэтому полноценная сборка
для ESP32, прошивка платы и проверка конкретного NV3007 не выполнены.
Готовый бинарник не прилагается. Перед использованием требуется сборка в IDE
и проверка на вашей плате, включая ориентацию, цвета и управление подсветкой.

Выполнены локальные проверки:

- C-модуль масштабирования с UndefinedBehaviorSanitizer: сохранение чистых
  RGB565-цветов, совпадение при масштабе 1:1, источник 1×1, все 142 выходные строки;
  одинаковый результат для обоих порядков байтов и неизменность входного буфера.
- CAN-декодер с подставными часами и блокировками: скорость, её таймаут,
  отсутствие обновления удалённых часов и сохранение позиций битов valid.
- Проверка локальных заголовков и отсутствия ссылок на удалённые подсистемы.

Тесты в tests/ предназначены для обычного компьютера с C-компилятором,
они не заменяют компиляцию и аппаратную проверку ESP32. Запуск из папки скетча:

```sh
cc -std=c11 -Wall -Wextra -Werror -fsanitize=undefined -I src/display tests/test_scale.c src/display/hud_scale.c -o /tmp/hud_test_scale
/tmp/hud_test_scale
cc -std=c11 -Wall -Wextra -fsanitize=undefined -I tests/stubs -I . tests/test_decode.c can_decode.c psd_speedlimit.c -o /tmp/hud_test_decode
/tmp/hud_test_decode
```

Исходники Arduino_GFX и пример подключения:
https://github.com/moononournation/Arduino_GFX
https://github.com/moononournation/Arduino_GFX/blob/master/examples/PDQgraphicstest/Arduino_GFX_display.h

## Исправление v27.3 и проверка чёрного экрана

В `lvgl_port.cpp` теперь явно передана последовательность
`nv3007_279_init_operations` из Arduino_GFX для дисплея **2.79″**.
Предыдущий вызов конструктора соответствовал примеру для 1.65/1.68″.
Источник: https://github.com/moononournation/Arduino_GFX/blob/master/examples/PDQgraphicstest/Arduino_GFX_display.h

Распиновка сохранена из присланного проекта: SCK=4, MOSI=5, CS=2, DC=7,
RST=6, BL=1, CAN RX=8, CAN TX=9 (не подключать).
Поддержка LV_COLOR_16_SWAP=0 и 1 сохранена.

Если HUD всё ещё не показывает изображение, открой отдельно
`tools/nv3007_test/nv3007_test.ino` в Arduino IDE и загрузи на ту же плату.
Нужна только GFX Library for Arduino с `nv3007_279_init_operations`;
LVGL, PSRAM, CAN и BLE в этом тесте не используются.
Тест использует SPI 10 MHz и показывает красный, зелёный, синий и белый
цвета по кругу. BL предполагается активным высоким уровнем, как в проекте.
Если тест работает, а HUD нет — пришли лог основного скетча после Reset
(115200 бод), проверь QSPI PSRAM. Если тест тоже чёрный — пришли его лог
и фото подключения. Успешный begin() означает запуск SPI и отправку команд,
а не подтверждение ответа дисплея (MISO отсутствует).

Сборка ESP32 и проверка на физическом дисплее здесь не выполнены.

## Изменения v27.6 — уменьшение объёма вывода по SPI

После масштабирования каждая полоса изображения сравнивается с предыдущим
кадром. Неизменившиеся полосы не передаются; в изменившейся полосе
передаётся только прямоугольник изменённых пикселей. Удаление старых цифр
также учитывается. Первый кадр передаётся целиком.

Дополнительный буфер предыдущего кадра занимает 121552 байта PSRAM
(около 119 КиБ), помимо холста LVGL 178192 байта. Внутренняя память
под блок 428×8 остаётся прежней. Частота SPI сохранена: 20 MHz.
Макет v27.5, распиновка и инициализация 2.79″ сохранены.

LVGL по-прежнему рисует полный виртуальный холст, а масштабирование
обрабатывает весь кадр. Оптимизация уменьшает передачу по SPI; она
не ускоряет приход CAN/BLE-данных и не гарантирует устранение разрыва
кадра при сканировании матрицы. Измерение частоты кадров на ESP32 не выполнено.

Проверки на компьютере: восстановление изображения из изменённых
прямоугольников точно совпадает с исходным кадром, включая стирание,
крайние пиксели, последнюю неполную полосу и 100 случайных изменений.
Проверка выполнена с UndefinedBehaviorSanitizer.

## v28.0 — управление настройками по BLE

Добавлены переключатели PSD/VZE, RU/EN, км/мили, литры/галлоны США,
сохранение настроек и владельца в NVS, PIN по умолчанию **482731**
(`HUD_SETTINGS_PIN` в user_config.h) и привязка к одному телефону.
После привязки — адресная BLE-реклама для владельца. BOOT GPIO0 удерживать
5 секунд и отпустить: сбрасывается только телефон, настройки остаются.
GPIO1 остаётся подсветкой. Приоритет основного знака теперь VZE → PSD.
Подробная инструкция и UUID: **BLE_SETTINGS_ru.md**.

## Исправление v28.1 — повторное подключение Android

Адресная реклама заменена подключаемой анонимной рекламой без имени
и UUID, с фильтром владельца. Проверка identity address перенесена
с onConnect на завершение аутентификации, когда доступна разрешённая
идентичность телефона. Добавлены диагностические сообщения соединения.
NVS, PIN, настройки, разметка Flash и привязка из v28.0 сохраняются.
Не использовать Erase All Flash при загрузке, если нужно сохранить NVS.

## v29.0 — BLE OTA

Новый OTA-сервис доступен только привязанному аутентифицированному телефону.
Передача с контролем смещений, SHA-256 и валидацией ESP-IDF, отдельный COMMIT.
При незавершённой передаче текущий раздел остаётся загрузочным.
Полная инструкция: ../docs/OTA_ru.md; схема: ../schematics/.
