# OTA через BLE — HUD v29.0 / Android HUD Control 1.2

## Первая установка — только USB

Текущая v28.2 имеет один factory-раздел. OTA не может заменить таблицу разделов.
Первую установку **v29.0 с приложенным partitions.csv** выполнить через USB.
Открыть `supermini_hud/supermini_hud.ino` и оставить рабочие параметры платы
ESP32-S3 Super Mini, 4 MB Flash, 2 MB QSPI PSRAM и прежние библиотеки.

**Erase All Flash = Disabled.** Начальная USB-загрузка должна записать новый
bootloader, таблицу разделов и приложение; старое приложение занимает тот же
начальный адрес 0x10000. В журнале сборки/прошивки проверить, что выбрана
таблица из папки этого скетча и загружается новая таблица по адресу 0x8000.
Если IDE применяет встроенную схему вместо custom `partitions.csv`, остановить
миграцию и исправить выбор таблицы. Один `.bin` приложения новую таблицу не устанавливает.

| Раздел | Начало | Размер |
|---|---:|---:|
| NVS | 0x9000 | 0x5000 = 20 KiB |
| otadata | 0xE000 | 0x2000 = 8 KiB |
| app0 | 0x10000 | 0x1F0000 = 1 984 KiB |
| app1 | 0x200000 | 0x1F0000 = 1 984 KiB |
| coredump | 0x3F0000 | 0x10000 = 64 KiB |

Один OTA-файл: не более **2 031 616 байт**. Предыдущая прошивка 1 061 616 байт
помещалась с запасом, но размер новой v29.0 нужно проверить после сборки.
NVS остаётся по прежнему адресу и с прежним размером: настройки, владелец и
ключи сопряжения должны сохраниться при USB-прошивке без полного стирания.
BOOT-привязку ради OTA не сбрасывать.

После USB-загрузки Serial 115200 должен показать:

```text
[fw] HUD Super Mini v29.0 / BLE OTA
[ota] BLE service ready, next slot capacity=2031616
```

Если capacity=0 — OTA-разметка не установлена: проверить partitions.csv.
При первой версии с новым сервисом прошивка посылает Service Changed для
старого GATT-кэша Android. Приложение может попросить переподключиться.
Если OTA-сервис всё ещё не виден, сначала выключить/включить Bluetooth телефона,
перезапустить HUD и подключиться вновь. Сопряжение не удалять без необходимости.

## Обновить приложение

Обновить исходники отдельного [Android-приложения](https://github.com/WARMW00D/HUD-Audi-A4-B9-MLB-Evo-Android-App) и пересобрать APK. applicationId прежний,
версия приложения 1.2; устанавливать поверх существующего приложения с тем же
ключом подписи. Сохранённый адрес HUD и язык приложения должны остаться.
Gradle 8.9 / AGP 8.7.3. Использовать путь без кириллицы, например `D:\HUD\android`.
`prepare-and-build.ps1` собирает debug APK и запускает Android lint.

## Получить правильный .bin

Arduino IDE: Sketch / Скетч → **Export Compiled Binary / Экспорт бинарного файла**.
Для передачи выбрать **supermini_hud.ino.bin**, то есть отдельный образ приложения.
Не выбирать `*.bootloader.bin`, `*.partitions.bin`, `*.merged.bin` и полный
дамп Flash. Файл должен быть собран для этой платы и с OTA-совместимой разметкой.
Размер ограничен OTA-разделом даже если полная Flash имеет 4 MB.

Следующие версии исходников тоже должны сохранять два OTA-раздела и BLE OTA.
OTA не изменяет bootloader, partitions.csv, eFuse и аппаратные параметры платы.
Проверка заголовка подтверждает ESP32-S3 и тип образа приложения, но не доказывает,
что любая сторонняя ESP32-S3 прошивка совместима с этим HUD: выбирайте файл HUD.

## Передача с телефона

1. Отключить nRF Connect от HUD. Открыть HUD Control, подключиться обычным способом.
2. Внизу открыть раздел **«Обновление прошивки / Firmware update»**.
3. Нажать **«Выбрать .bin / Choose .bin»** и выбрать образ приложения.
4. Приложение проверит заголовок и размер, затем вычислит SHA-256.
5. Нажать **«Обновить HUD / Update HUD»**, проверить имя файла и подтвердить.
6. Держать приложение открытым, телефон рядом, питание HUD стабильным.
   Скорость зависит от Android и BLE; передача может занять несколько минут.
7. После передачи выполняются проверка SHA-256 и валидация образа ESP-IDF.
   100% на полоске означает передачу всех байтов, а не завершение проверки.
8. После отдельного подтверждения выбора загрузочного раздела HUD перезапустится.
   Подключиться заново, проверить графику, настройки и чтение CAN.

Для первой проверки можно передать тот же собранный v29.0 app `.bin` в соседний
OTA-раздел. Не проверять обрыв питания во время самого переключения otadata.

## Отмена и ошибки

Кнопка «Отменить передачу» доступна до команды переключения загрузочного
раздела. При отмене, обрыве до переключения, неправильном SHA-256 или неверном
образе новая прошивка не выбирается для следующей загрузки. Начать заново:
возобновление с промежуточного смещения в этой версии не реализовано.
Бездействие 120 секунд отменяет незавершённую сессию на HUD; Android ждёт ответ
на отдельную BLE-операцию не более 30 секунд.

Если подтверждение COMMIT потеряно, приложение **не объявляет обновление
неуспешным**: раздел мог уже переключиться. Оно просит дождаться перезагрузки
и проверить HUD перед повторной передачей. Перезапуск запланирован через две
секунды после успешного выбора boot-раздела, даже если телефон отключился.

| Код HUD | Причина |
|---:|---|
| 1 | Некорректный формат команды/пакета |
| 2 | Нет подходящей OTA-разметки |
| 3 | Размер не совпадает или не помещается |
| 4 | Ошибка Flash / SDK / выбора boot-раздела |
| 5 | Неверное смещение, пропуск или повтор блока |
| 6 | SHA-256 не совпал |
| 7 | Неверный образ, другой чип или ошибка проверки ESP-IDF |
| 8 | Команда в неверном состоянии |
| 9 | Таймаут сессии |

Все чтения/записи OTA требуют шифрованное, аутентифицированное сопряжение
и уже сохранённого владельца. Другой телефон не может начать передачу.
SHA-256 проверяет целостность; это не самостоятельная цифровая подпись прошивки.

Автоматический откат при **ошибке работы уже запущенной новой программы** здесь
не обещается: стандартный bootloader Arduino обычно не включает rollback.
Корректный бинарный формат не гарантирует отсутствие программных ошибок.
USB остаётся способом восстановления, если новая версия не запускается.

## Протокол v1

| Назначение | UUID |
|---|---|
| Сервис OTA | 74d0a200-3d92-4f50-9b1a-478142000001 |
| Control: READ / WRITE с ответом | 74d0a200-3d92-4f50-9b1a-478142000002 |
| Data: WRITE с ответом | 74d0a200-3d92-4f50-9b1a-478142000003 |

У всех характеристик требуется аутентификация. Notifications не используются.
Числа — little-endian. START: `01 + uint32(size) + SHA256[32]`, 37 байт.
Data: `uint32(offset) + 1…240 байт`. Первый блок содержит минимум 36 байт образа.
END `02` проверяет полный файл. COMMIT `03` выбирает его для загрузки.
ABORT `04` отменяет незавершённую сессию.

Control READ возвращает 16 байт: версия протокола (1), состояние, код ошибки,
нулевой резервный байт, uint32(received), uint32(total), uint32(capacity).
Состояния: 0 Idle, 1 Receiving, 2 Verified, 3 Committed, 4 Error.
Приложение согласует MTU (минимум 64), передаёт один блок за раз и читает
подтверждённое смещение после каждого блока. Изменение обычных настроек во время
OTA заблокировано в приложении. Язык самого приложения можно переключать.

## Что проверено здесь

Host-проверки C++ с настоящим SHA-256 (OpenSSL), имитацией NimBLE/ESP-IDF:
полная передача, переключение только после верификации, потеря финального ACK,
повтор COMMIT, плохой hash, неверный чип/образ, ошибки Flash, неправильное смещение,
переполнение/неполный файл, отмена, отключение, таймаут и отказ чужому телефону.
Регрессия BLE-настроек/NVS прошла. Ветки API mbedTLS 2/3 прошли на host-адаптере.
Также проверены таблица разделов, UUID и RU/EN ресурсы.

**Сборка ESP32 и APK, валидация реального ESP-IDF образа, Service Changed Android
и передача на вашей плате не проверены: соответствующих toolchain здесь нет.**
Host-моки не заменяют проверку реального BLE и Flash.
