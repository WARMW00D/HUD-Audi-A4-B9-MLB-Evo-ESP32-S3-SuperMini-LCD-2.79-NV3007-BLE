# Настройки HUD по BLE — v29.1

Открыть основной `supermini_hud.ino` из этого архива. Нужен NimBLE-Arduino
**2.5.1** (API 2.x). LVGL остаётся 8.4.0. Графика и GPIO дисплея не менялись.
Потребуются роли NimBLE central + peripheral, legacy advertising и минимум
два соединения для телефона и CAN-шлюза одновременно. Обычная конфигурация
NimBLE-Arduino поддерживает эти роли; нестандартные настройки библиотеки проверить.

## Первое подключение

1. Включить HUD. До привязки он доступен как **HUD-SuperMini**.
2. Открыть BLE-клиент на телефоне, например nRF Connect, найти HUD и подключиться.
3. В системном запросе сопряжения ввести PIN из `HUD_SETTINGS_PIN` в `user_config.h`. Если приложение предлагает
   Bond / сопряжение, выполнить его. Простого подключения без PIN недостаточно.
4. Открыть сервис `74d0a100-3d92-4f50-9b1a-478142000001`.
5. Для нужной характеристики выполнить Read или Write с ответом в формате Hex.
   Передавать ровно один байт: `00`/`01` для переключателей, `01`..`C8` для объёма бака (1..200 л). Это число, не текстовые символы.
6. После записи выполнить Read: прочитанное значение подтверждает сохранённую настройку.

| Настройка | UUID характеристики | `00` | `01` |
|---|---|---|---|
| PSD | `74d0a100-3d92-4f50-9b1a-478142000002` | выключить | включить |
| VZE | `74d0a100-3d92-4f50-9b1a-478142000003` | выключить | включить |
| Язык | `74d0a100-3d92-4f50-9b1a-478142000004` | RU | EN |
| Скорость и расстояние | `74d0a100-3d92-4f50-9b1a-478142000005` | км/ч, км, м | mph, mi, ft |
| Объём для долива | `74d0a100-3d92-4f50-9b1a-478142000006` | литры | галлоны США |
| Бар ускорения | `74d0a100-3d92-4f50-9b1a-478142000008` | выключить | включить |

Объём бака: `74d0a100-3d92-4f50-9b1a-478142000007`, один беззнаковый байт, 1..200 л. Например, 54 л = `36`, 63 л = `3F`, 200 л = `C8` (Hex). Единицы ввода всегда литры; настройка галлонов влияет только на отображение долива. Нулевой объём и многобайтовые записи отвергаются.

Толерантность: `74d0a100-3d92-4f50-9b1a-478142000009`, один байт `00`..`64` (0..100 км/ч); по умолчанию 20 (`14` Hex). Ноль — красная обводка при любом превышении; иначе прежнее плавное появление от 75% допуска. Единицы ввода — км/ч независимо от режима mph.

Новые характеристики требуют приложения 1.3 и прошивки v29.1. В NVS используются отдельные ключи `tank-l`, `accel-bar`, `speed-tol`; запись прежних настроек/владельца остаётся совместимой. GATT schema marker = 3: после обновления переподключить телефон.

Настройки применяются при следующем обновлении интерфейса и сохраняются
автоматически в NVS через Preferences, в пространстве `hud-settings`.
Записываются только изменения. Некорректные значения игнорируются.
Если сохранение не удалось, настройка остаётся прежней; это видно при Read
и в Serial. Константы HUD_PSD_LIMITS, HUD_VZE_SIGNS, HUD_LANG, HUD_UNITS,
HUD_VOLUME_GAL, HUD_TANK_L, HUD_ACCEL_BAR и HUD_OVERSPEED_TOL_KMH задают начальные значения, когда в NVS ещё нет настроек.
После появления сохранённой записи изменение констант её не перезаписывает.

## PIN и безопасность

В `user_config.h`:

```cpp
// HUD_SETTINGS_PIN задаётся в user_config.h
#define HUD_SETTINGS_BLE_NAME "HUD-SuperMini"
#define HUD_SETTINGS_BOOT_PIN 0
#define HUD_SETTINGS_BOOT_HOLD_MS 5000
```

Это PIN **телефона**, независимый от `BLE_PASSKEY` CAN-шлюза в `secrets.h`.
Телефон должен завершить аутентифицированное зашифрованное сопряжение с bonding.
Первый успешно сопряжённый телефон становится единственным владельцем.
Его identity address и тип сохраняются в одной записи NVS с настройками;
ключи/IRK сохраняет NimBLE в своей NVS. Проверяется identity address,
а не временный случайный адрес телефона. Каждое чтение и запись требуют
принадлежности владельцу и аутентифицированного зашифрованного соединения.

После привязки используются обычные подключаемые BLE-пакеты без имени
и списка сервисов, с non-discoverable флагами и фильтром допустимого адреса
владельца. Адресная (directed) реклама из v28.0 заменена для совместимости
с Android. Посторонний BLE-сканер может видеть анонимные пакеты; полного
отсутствия в эфире скрытый режим не обеспечивает. Общая регистрация новых
телефонов закрыта, каждый доступ к настройкам требует сохранённых ключей
и identity address владельца. В onConnect адрес ещё может быть временным:
окончательная проверка выполняется после аутентификации/шифрования.

Повторное подключение делать из сохранённого/сопряжённого устройства
в приложении. Если искать сканированием, запись может отображаться
без имени: ориентироваться на сохранённый адрес HUD. Не удалять
сопряжение телефона и не сбрасывать BOOT при установке v28.1.
Прошивка не меняет формат NVS и сохраняет существующую привязку.
Если проблема сохраняется, нужен лог после подключения и перезапуска:
`Link connected`, `Owner authenticated`, `Auth rejected` или ошибка рекламы.

Если на телефоне удалить сопряжение, заново вводить PIN без сброса HUD нельзя:
сначала сбросить привязку кнопкой BOOT. Изменение PIN в константе не отзывает
уже сохранённые ключи: для нового PIN тоже сбросить привязку и удалить старое
сопряжение на телефоне.

## Сброс телефона

На работающем HUD удерживать **BOOT 5 секунд, затем отпустить**.
В Serial появится просьба отпустить BOOT; после отпускания HUD удалит
привязку и ключи только телефона, перезапустится и откроет общее сопряжение.
Выбранные настройки и ключи CAN-шлюза сохраняются. Чтобы повторно привязать
тот же телефон после сброса, удалить на нём прежнее сопряжение HUD.
Короткое нажатие ничего не меняет.

BOOT у ESP32-S3 — **GPIO0**, активный низкий уровень. GPIO1 остаётся подсветкой.
Не держать BOOT при включении питания или нажатии RESET: это вход в загрузчик.
Если BOOT конкретной платы подключён иначе, сверить схему платы и изменить
HUD_SETTINGS_BOOT_PIN. Источник:
https://docs.espressif.com/projects/esptool/en/latest/esp32s3/advanced-topics/boot-mode-selection.html

## Совместная работа с CAN-шлюзом и приоритет знаков

NimBLE инициализируется один раз; HUD одновременно предоставляет сервис
телефону и работает клиентом CAN-шлюза. При первом PIN-сопряжении шлюза
на короткое время закрывается подключение телефона: IO capability NimBLE
общая для обеих ролей. Если телефон уже подключён, первое сопряжение
нового шлюза откладывается до отключения телефона. Переподключение к уже
сопряжённому шлюзу может выполняться вместе с телефоном.

Раньше основной знак выбирался как явный PSD → VZE → PSD по правилам.
Теперь **действующий VZE имеет приоритет над PSD**. Если VZE выключен,
невалиден или подавлен, используется PSD (если он включён). При выключении
обоих источников основной знак скрывается. Дополнительные знаки VZE
по-прежнему могут показываться по очереди. PSD-запрет обгона не добавляется
поверх действующего основного VZE. Контроль превышения берёт основной знак.

## Что проверено

Проверки на компьютере: выбор основного знака на коде из hud_mockup.c;
модель callbacks BLE и NVS — владелец, отклонение чужого/незащищённого
соединения, пять настроек, неправильные значения, ошибка записи, восстановление
сохранённых значений, переход в анонимный режим с фильтром, тип identity address после
разрешения RPA, защита от одновременного PIN-сопряжения и BOOT 5 секунд.
Также прошли проверки масштабирования и частичного вывода изображения.

Модель использует заглушки библиотек; она не заменяет компиляцию настоящего
NimBLE/ESP32 SDK. Сборка ESP32, PIN-диалог телефона, повторное подключение,
работа с CAN-шлюзом и потребление памяти требуют проверки на вашей плате.

Модель BLE/NVS можно повторить на компьютере с g++:

```sh
g++ -std=c++17 -Wno-deprecated-declarations -Itests/settings_stubs tests/test_ble_settings.cpp -lcrypto -o test_ble_settings
./test_ble_settings
```
